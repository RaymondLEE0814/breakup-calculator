## 1. 왜 다시 만들었나

클라이언트 지적은 "문항과 계산방식이 고리타분하다"였고, 이것은 문장 스타일이 아니라 **측정 구조**의
문제였습니다. v1의 다섯 가지 결함:

1. **투명 문항.** "다툴 때 대화는 어떻게 흘러가나요?"는 어느 답이 나쁜 답인지 즉시 보입니다.
   응답자가 관계를 측정받는 대신 인상을 관리하게 됩니다.
2. **인구통계 문항의 낮은 정보량.** 나이 차이, 교제 기간은 개별 커플 수준에서 예측력이 거의 없으면서
   "조건으로 사람을 매긴다"는 인상만 남겼습니다. v2에서 채점 문항으로는 전량 삭제했습니다.
3. **축이 이론이 아니라 편의 분류.** "행동/구조/경제/전망"은 기사 카테고리입니다. 관계 해체 연구가
   실제로 쓰는 변수 — **대안의 질, 투자 규모, 헌신, 제약, 해체를 향한 행동 단계** — 가 통째로
   빠져 있었습니다.
4. **단순 가중합의 한계.** 외부 스트레스는 갈등 대처가 나쁜 커플에서만 파괴적이고, 제약은 헌신이
   낮을 때만 시한폭탄입니다. 선형 모델은 이 구조를 표현할 수 없습니다.
5. **4지선다 명목형.** 빈도·강도처럼 연속적인 차원에서 정보가 손실되고, 선택지 문구마다 점수를
   짐작할 단서가 생겼습니다.

## 2. 여섯 개 구성

| | 심플형 (선별) | 심화형 (진단) |
|---|---|---|
| 목적 | 검색 유입이 이탈 전에 숫자를 본다 | 진지하게 고민 중인 사람이 구조를 이해한다 |
| 문항 | 7문항 / 1분 | 32~34문항 + 안전 문항 / 7~9분 |
| 결과 | 지수 ±7 + 등급 + 한 줄 진단 + 심화 유도 | 지수 + 차원 프로파일 + 유형 + 실행 처방 |

**심플형은 심화형의 축약이 아니라 다른 도구입니다.** 선별(screening)과 진단(profiling)의 차이이며,
두 결과가 다를 수 있다는 사실을 `/about`과 결과 화면에서 명시합니다.

| 계산기 | 경로 | 문항 | 핵심 프레임 |
|---|---|---|---|
| 헤어질 확률 계산기 | `/breakup` | 7 | 초단축 만족 + 대안 + 경멸·요구철회 + 행동 단계 |
| 연애 관계 심화 진단 | `/breakup/deep` | 33 | **투자모형** + Gottman 갈등 과정 + 애착 2차원 + VSA |
| 이혼 확률 계산기 | `/divorce` | 7 | 만족 3문항 구조 + 경멸·요구철회 + 헌신 + 행동 단계 |
| 부부 관계 심화 진단 | `/divorce/deep` | 34 | **VSA** + Gottman + 헌신·제약 분리 + PREPARE/ENRICH 영역 |
| 황혼 이혼 계산기 | `/twilight` | 7 | 만족 + 담쌓기·경멸 + **제약 인식** + 헌신 + 행동 단계 |
| 황혼 부부 심화 진단 | `/twilight/deep` | 32 | **헌신–제약 분리 중심** + Levinger + Gottman + 후기 스트레스 |

기존 3개 URL은 그대로 심플형이 됩니다. 리다이렉트 없음 — 검색 의도("헤어질 확률 계산기")와 심플형의
성격이 정확히 일치하므로 SEO상으로도 올바른 배치이고, 색인과 백링크가 보존됩니다.

### 이론 배정 근거 두 가지

- **연애 심화형에 대안의 질이 핵심인 이유** — 미혼 관계에는 재산·절차·자녀 같은 제도적 장벽이
  없습니다. 남는 것은 심리적 계산(만족한가 / 떠나면 더 나은가 / 쌓아 둔 것이 아까운가)이고, 이것이
  정확히 투자모형의 세 입력입니다. v1은 이 중 만족 비슷한 것만 재고 있었습니다.
- **황혼 심화형에 헌신–제약 분리가 결정적인 이유** — "30년을 같이 살았다"는 지속의 기록이지 안정의
  증거가 아닙니다. 헌신 없이 제약(자녀·시선·경제 의존)만으로 유지된 관계는 제약이 풀리는 은퇴·자녀
  독립 시점에 무너집니다. 합산하면 이 구조가 보이지 않고, 분리해 **격차를 곱셈 항으로** 넣어야만
  보입니다.

## 3. 측정 설계 원칙

`src/lib/calc/scales.ts`가 척도를 정의하고, 문항 config가 이 원칙을 따릅니다.

- **행동 빈도·장면 문항이 절반 이상.** "지난 한 달 동안 몇 번", "그때 보통 어떻게 되나요". 태도
  자기평가는 만족·헌신처럼 본질이 태도인 차원에만 씁니다.
- **역채점은 데이터로.** 동의 문항의 절반가량이 긍정 진술이며, 점수 배열을 뒤집어 기재합니다
  (`AR` 척도). 엔진은 역채점의 존재를 몰라도 됩니다.
- **5점 리커트.** 빈도·동의 차원 전부. 문항 만점은 4점으로 통일(v1의 0~10점 폐기).
- **선택지 순서 ≠ 점수 순서.** 장면 문항의 점수가 0-2-3-4처럼 비단조인 것은 의도입니다.
- **양방향 귀속.** "내가 하든 상대가 하든" — 자기 잘못을 인정하라는 압박을 제거합니다.
- **시간 창 고정.** "지난 한 달", "지난 세 달". 인상 평가가 아니라 회상 과제로 만듭니다.

### 안전 문항 (심화형 3종, 미채점)

첫 화면에 `S0`를 두고 폭력·통제·반복적 모욕을 확인합니다. "있다"를 골라도 검사는 계속 진행되며,
결과 화면 최상단에 상담 안내 배너가 붙습니다. **이 응답은 채점·저장·공유 어디에도 쓰이지
않습니다** — 테스트가 이를 강제합니다.

## 4. 계산식

```
D_j    = round(100 × 차원 획득점수 / 차원 만점)          # 0–100
DED_eff = 0.5×D_DED + 0.5×(0.5×D_SAT + 0.3×D_ALT + 0.2×D_INV)   # 연애 심화형만
I      = D_STR × D_ADP / 100                            # 압력 × 대처
G      = D_DED × D_CNS / 100                            # 헌신 없는 제약
S      = Σ(w_j × D_j) + Σ(w_term × term)                # 0–100
R      = 5 + 80 / (1 + e^(−0.07 × (S − 45)))            # 5–85
R      = max(R, floor)  if 위험 플래그 발동              # 상한 85 유지
```

여섯 계산기가 동일한 로지스틱 상수를 씁니다. "심플 42% → 심화 51%"가 해석 가능한 문장이 되어야 하기
때문입니다. 참조값은 `tests/calc.test.mjs`가 고정합니다.

| S | 0 | 25 | 45 | 65 | 85 | 100 |
|---|---|---|---|---|---|---|
| R | 8.3 | 20.8 | 45.0 | 69.2 | 80.4 | 83.3 |

**최선 8 / 최악 83.** v1에서 최선이 9였던 것은 교제·혼인 기간 문항이 기본 위험을 깔았기
때문인데, v2에서 그 문항들을 없애면서 곡선의 실제 하한에 닿습니다.

**제약(CNS)은 가중치 0입니다.** 제약이 높다는 것 자체는 위험이 아니고 — 헌신이 높으면 오히려 안정
요인입니다 — 헌신 위험과 곱해질 때만 위험이 됩니다. 이것이 헌신–제약 이론의 계산적 번역이며,
테스트가 "제약만 최대여도 지수가 8에서 움직이지 않는다"를 검증합니다.

**위험 플래그.** 이별·이혼을 향해 실제로 움직인 단계를 묻는 문항은 지수에 하한을 겁니다. 복수 발동
시 가장 높은 하한 하나만 적용하고, 발동 사실과 이유를 결과 화면에 표시합니다.

**top 요인**은 선형 항 기여분으로만 계산합니다. 상호작용 항은 문항 단위로 분해하는 것이 수학적으로
애매하므로 별도 카드로 노출합니다.

## 5. 결과 화면

- **심플형** — 지수 ±7, 등급, 한 줄 진단(최대 기여 차원), top 3 요인, **심화형 유도 카드**(핵심
  동선), 공유.
- **심화형** — 안전 배너(해당 시), 지수, 등급, 차원 프로파일(제약은 중립색 + "직접 반영 안 함"
  표기), 상호작용 카드, **유형 분류**, top 3 요인 + 실행 처방, 플래그 설명, 공유.

유형은 2×2, 각 축 50 기준:

| 계산기 | 축 | 유형 |
|---|---|---|
| 연애 심화 | 만족 × 헌신 | 동행형 / 표류형 / 관성형 / 갈림길형 |
| 부부 심화 | 상호작용 × 헌신 | 한 팀형 / 룸메이트형 / 과열형 / 소진형 |
| 황혼 심화 | 헌신 × 제약 | 동반자형 / 책임동행형 / 각자생활형 / 형식유지형 |

## 6. 결과 카피 구조

`factors.ts`(v1, 문항 id 키) + `factors-v2.ts`(v2, **구성개념 키**)를 병합해 씁니다.

여섯 계산기가 경멸을 묻지만 경멸은 하나이고, 그에 대한 처방도 하나입니다. 구성개념으로 키를 잡으면
같은 카피를 여섯 번 쓰고 따로 낡아가는 일이 없습니다. 문항은 `factor` 필드로 자기 구성개념을
가리키며, 생략하면 자기 id가 키가 됩니다.

v1 항목은 **삭제 금지**입니다. 구모델로 생성된 공유 링크가 아직 살아 있습니다.

## 7. 데이터와 마이그레이션

`supabase/migrations/20260825000000_six_calculators.sql`:

- `calc_type` 체크 제약을 6종으로 확장
- `model_version smallint default 1` — 기존 행이 자동으로 v1로 분류되므로 backfill 불필요
- `type_code` — 심화형 유형, 12개 코드 체크
- `stats_summary` 뷰를 모델 버전별로 분리 (v1 지수와 v2 지수는 다른 도구의 산출물이라 섞어 평균
  내면 무의미)

**공유 링크 호환** — `src/lib/shared-registry.ts`가 `(calc_type, model_version)`으로 라벨 세트를
돌려줍니다. v1 행은 구 축 라벨로 렌더되고, 구모델 결과임을 알리는 한 줄이 붙습니다. 이미 뿌려진
링크는 전부 그대로 동작합니다.

**진행 중 세션** — sessionStorage 키에 모델 버전을 넣었습니다(`calc:breakup:v2`). 배포 순간 절반쯤
풀던 사용자는 처음부터 다시 풀게 되지만, 구 답안을 신 모델에 욱여넣는 것보다 정직합니다.

## 8. 정직성 고지 (/about)

새 모델에서도 이 페이지가 가장 중요한 신뢰 자산입니다. 공개하는 것:

1. 문항 구조는 검증된 도구·모형을 참고해 **새로 작성**한 것이며, **이 검사 자체의 예측 타당도는
   검증된 적이 없다**는 사실. 가중치와 상수는 설계 판단입니다.
2. 지수는 확률이 아니며 5~85로 제한된 이유.
3. 한 사람의 자기보고라는 한계, 두 사람이 각자 답해 비교하라는 권유.
4. 심플형과 심화형이 다를 수 있다는 점과 ±7의 이유.
5. 폭력·통제는 범위 밖이라는 점과 상담 연락처.

## 9. 2차 과제

1. 슬러그별 동적 OG (Worker가 Supabase를 조회해 등급·유형별 og:image 주입)
2. 집계 통계 노출 (n ≥ 100, 모델 버전별)
3. 커플 비교 모드 — 두 사람의 심화 결과를 한 화면에서
4. 레이더 차트, 결과 이미지 저장, 카카오톡 공유
5. Turnstile 어뷰징 방어, slug 조회 전용 RPC
6. 나머지 가이드 아티클 5편 (심화형 차원을 설명하는 글로 재구성)
