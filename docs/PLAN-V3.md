## 0. 원칙과 부딪히는 지점 — 먼저 정리

이번 개편은 기존 원칙 세 가지를 스칩니다. 어떻게 지켰는지부터 적습니다.

**"응답은 기기 밖으로 나가지 않는다" vs 상담 신청 폼.** 검사 응답과 신청서는 다른 데이터입니다.
문항별 답변은 지금도 서버로 가지 않습니다. 폼은 별도 화면에서 별도 동의를 거쳐 이용자가 직접
입력해 제출하는 신청서이고, 검사 결과 **요약조차** 체크박스를 켰을 때만 함께 갑니다. 개별 응답은
어떤 경로로도 실리지 않습니다. 홈 FAQ·계산기 FAQ·`/privacy` 세 곳의 문구를 이 구분이 드러나게
다시 썼습니다.

**"결과를 단정하지 않는다" vs 과실 계산기.** 과실 비율은 위험 지수보다 단정의 유혹이 큽니다.
그래서 결과 최상단에 "법률 판단이 아니며 증거에 따라 결론이 달라진다"를 고정하고, 5%p 반올림 ·
정성 밴드 · 판단 유보 규칙으로 과잉 정밀도를 눌렀습니다.

**"이혼하세요로 밀지 않는다".** 지수가 아무리 높아도 부부상담 카드는 화면에서 사라지지 않습니다.
법률 트랙은 "결정을 재촉"이 아니라 "이미 알아보기 시작한 사람에게 정돈된 정보를"로만 포지셔닝합니다.

## 1. 진입 구조

| 경로 | 성격 | 색인 |
|---|---|---|
| `/breakup` `/divorce` `/twilight` | **허브** — 기본/심화 선택 + 크롤 가능 본문 | index |
| `/*/quick` | 빠른 검사 7문항 | index |
| `/*/deep` | 심화 진단 | index |
| `/*/quick/result` `/*/deep/result` | 결과 | noindex |
| `/divorce/fault` | 과실(유책) 비율 계산기 | index |
| `/divorce/fault/result` | 과실 결과 | noindex |
| `/counseling` `/legal` | 상담 신청 (안내 + 폼) | index |
| `/*/done` | 접수 완료 | noindex |

**기존 3개 URL은 리다이렉트하지 않습니다.** 같은 URL이 허브로 역할만 바꿉니다. 색인·백링크·순위가
그대로 유지되는 것이 이 설계의 핵심이고, 그래서 허브가 얇은 선택 화면이 되면 안 됩니다. 빠른 검사
페이지가 갖고 있던 **문항 미리보기·FAQ·JSON-LD를 허브가 전부 상속**하고, "어떤 검사를 골라야
하나요" 본문을 새로 더해 오히려 분량이 늘었습니다. 퀴즈 UI만 한 단계 내려갔습니다.

구 결과 URL(`/breakup/result` 등) 3건은 Worker가 301로 새 위치에 보냅니다. SEO 자산은 없지만
북마크한 사람에 대한 예의입니다.

## 2. 이혼·황혼 결과의 분기

경계는 **지수 50**, 즉 점검/주의의 경계입니다. 새 숫자를 만들지 않고 이미 고지된 등급 체계를
재사용합니다. 위험 플래그(이혼을 입 밖에 냄 = 하한 50, 별거·절차 = 50~65)가 전부 50 이상에 하한을
걸기 때문에, "이혼을 향해 실제로 움직인 사람"은 구조상 반드시 50 이상이고 법률 트랙이 노출되어야 할
집단과 자연스럽게 일치합니다.

| 등급 | 제안 |
|---|---|
| 안정 (≤29) | 카드 없음. 조용한 텍스트 링크로 부부상담만 |
| 점검 (30~49) | 부부상담 카드 (예방 프레임) |
| 주의 (50~67) | 부부상담 카드 + 법률 정보 축소형 |
| 경고 (68~85) | 부부상담 카드 + 법률 정보 표준형 |

**빠른 검사에서 45~54는 분기하지 않습니다.** ±7 밴드가 경계를 걸치는 구간에서 7문항짜리 결과로
다음 걸음을 가르는 것은 도구의 정밀도를 초과합니다. 이 구간은 심화 진단 권유 단독 카드로 갑니다.

**유형은 순서와 리드 문장만 바꿉니다.** 과열형·책임동행형처럼 마음이 남아 있는 유형은 상담을 크게
두고 법률을 축소형으로 내립니다. 플래그로만 지수가 올라간 경우(구조 점수는 낮은데 이미 움직인 걸음이
있는 경우)는 그 사실을 먼저 설명하고 두 카드를 나란히 둡니다.

**안전 문항이 발동하면 분기를 통째로 걷어냅니다.** 폭력·통제 관계에서 부부 동반 상담은 피해자를
위험에 빠뜨릴 수 있고, 과실 비율을 따지게 하는 것은 피해자의 자기귀책을 부추깁니다. 안전 배너에
대한법률구조공단 132를 더하고, 카드는 하나도 렌더링하지 않습니다.

**분기 판정은 전부 클라이언트에서** 세션의 결과로만 합니다. 어떤 카드를 봤는지도 서버로 보내지
않습니다. 폼으로 갈 때 쿼리스트링에 붙는 것은 `?from=divorce-deep` 같은 **출처 라벨뿐**이고, 지수는
싣지 않습니다.

## 3. 과실(유책) 비율 계산기

민법 제840조의 재판상 이혼 사유 여섯 가지 중 다섯을 차원으로 삼습니다. "3년 이상의 생사불명"은
문답 상황과 양립하지 않아 제외하고, 그 사실을 결과 화면에 적습니다.

| 차원 | 근거 | 가중치 |
|---|---|---|
| 부정행위 | 1호 | 0.25 |
| 심히 부당한 대우 | 3호 | 0.20 |
| 악의의 유기 | 2호 | 0.15 |
| 경제적 신뢰 훼손 | 6호 범주 | 0.15 |
| 공동생활 파탄 기여 | 6호 범주 | 0.15 |
| 직계존속 관련 | 3호·4호 | 0.10 |

### 산출 방식이 다른 이유

로지스틱 5~85 매핑을 쓰지 않습니다. 그 장치는 절대적 위험 점수가 확률처럼 읽히지 않게 누르는
용도인데, 비율은 애초에 두 값의 상대 배분이라 이미 유계이고 로지스틱을 씌우면 입력만 왜곡됩니다.
과잉 정밀도는 다른 방식으로 눌렀습니다.

```
문항 점수 s(0~4) × 방향 배분 σ (주로 상대 0.15 / 양쪽 0.5 / 주로 나 0.85)
차원별 정규화 → 가중합 → S_me, S_sp
비율 = S_sp / (S_me + S_sp), 5%p 단위 반올림
S_me + S_sp < 8 이면 비율을 표시하지 않는다
```

**양쪽을 같은 문장으로 묻습니다.** 상대의 잘못만 묻는 계산기는 분쟁을 부추기고 정확하지도
않습니다. 문항 수가 두 배가 되는 것을 막으려고, 정도를 먼저 묻고 **0점이 아닐 때만** 방향을
이어서 묻습니다. 체감 12문항, 최대 24화면.

### 넘지 않는 선

위자료·재산분할 금액을 산출하지 않고, 승소 가능성을 말하지 않으며, 증거 수집 방법을 조언하지
않습니다. 판례 번호·법원명·통계 수치를 인용하지 않고, 조문은 제840조의 문언 수준까지만 씁니다.
"당신은 유책배우자입니다"라는 단정 문장을 쓰지 않고, 결과를 공유 링크로 만들지 않습니다.

## 4. 상담 신청 폼

이 서비스가 처음으로 연락처를 받는 기능입니다.

**제휴 기관명이 없으면 폼이 열리지 않습니다.** 개인정보보호법상 제3자 제공 동의에는 제공받는 자를
명시해야 하는데, "미정" 상태로 전화번호를 받을 수는 없습니다. `src/lib/partners.ts`의 값이 `null`인
동안 두 페이지는 안내 본문만 렌더링하고, 이름을 채우면 그 자리에 폼이 열립니다.

**수집 항목은 최소한으로.** 실명을 요구하지 않고(호칭이면 충분), 주소는 대면 상담일 때 시·도까지만
받고, 이메일은 받지 않습니다. 배우자의 정보는 어떤 항목으로도 받지 않습니다.

**동의는 두 개, 각각 별도, 기본 해제.** 수집·이용 동의와 제3자 제공 동의를 나누고, 각각의 고지
항목(수집 항목/목적/보유 기간/거부 권리, 제공받는 자/목적/항목/보유 기간/거부 권리)을 `<details>`로
제공합니다. 두 체크 없이는 제출 버튼이 비활성입니다. 동의 시각을 각각 저장합니다.

**검사 결과는 옵트인, 요약까지만.** 지수·등급·유형까지이고 차원 점수와 개별 응답은 보내지 않습니다.
과실 계산기에서 온 경우 비율 구간(`sp60_70`)과 상위 사유 두 개까지입니다. URL로 결과값을 나르지
않고, 체크했을 때 폼 스크립트가 세션에서 직접 읽습니다.

**RLS는 `shared_results`와 정반대입니다.** anon은 **insert만** 가능하고 select/update/delete 정책이
아예 없습니다. 전화번호가 든 행은 브라우저에서 읽을 수 없어야 합니다. 그래서 클라이언트 insert에
`.select()`를 체이닝하지 않습니다 — 붙이면 읽기 정책이 필요해집니다.

**보관 90일.** `pg_cron`으로 일 1회 정리하거나, 플랜이 안 되면 월 1회 수동 파기를 운영 절차로
둡니다. 고지 문구가 "90일 후 지체 없이"라 월 단위 정리에도 여유가 있습니다.

**스팸 대비**는 이번 단계에서 과설계하지 않습니다: 허니팟, 최소 체류 시간 5초, DB 제약으로
이중화한 형식 검증, 제출 토큰 unique로 중복 방지. 신청량이 생기면 Worker 프록시 + Turnstile로
승격합니다.
