## 1. 서비스 정의와 포지셔닝

**한 줄 정의** — "지금 우리 관계, 괜찮은 걸까?" 연인·부부·황혼 부부가 15~18개 질문에 답하면,
관계의 위험 신호를 네다섯 개 축으로 수치화해 담담하게 보여주는 무료 자가진단 계산기.

| 타깃 | 계산기 | 핵심 고민 | 검색 트리거 |
|---|---|---|---|
| 연인 (20~30대) | `/breakup` | 요즘 자주 싸우는데, 헤어지는 건 아닐까 | 큰 싸움 직후, 권태기, 장거리 |
| 부부 (30~50대) | `/divorce` | 우리 결혼, 안전한 걸까 | 반복 갈등, 경제 문제, 시가·처가, 각방 |
| 황혼 (50대+, 혼인 20년+) | `/twilight` | 은퇴하고 나니 하루 종일 부딪힌다 | 은퇴, 자녀 독립, 졸혼 뉴스 |

### 경쟁 서비스와의 차별점

| 구분 | 기존 궁합·매칭 계산기 | 본 서비스 |
|---|---|---|
| 입력 | 이름, 생년월일, MBTI | 실제 관계 행동 + 구조·경제 요인 |
| 근거 | 무근거 난수 / 신비주의 | 관계 연구 + 통계 경향 기반 공개 휴리스틱 |
| 결과 | "궁합 92%!" | 위험 지수 + 축별 분해 + top 3 요인 + 실행 제안 |
| 투명성 | 비공개 | 전 문항 배점·가중치·계산식 `/about`에 공개 |
| 타깃 폭 | 연인 위주 | 연인 → 부부 → 황혼 (국내 유사 서비스가 없는 구간) |

### 톤&매너 3원칙

1. **단정하지 않는다.** "당신은 헤어집니다"가 아니라 "이런 신호가 보입니다". 결과 수치 옆에는 항상
   "정해진 미래가 아니다"라는 고지가 붙는다.
2. **사람을 서열화하지 않는다.** 키·소득·자산·학력의 **절대값을 입력받지 않는다.** 오직 격차의
   체감과 그로 인한 갈등 빈도만 점수화한다. "연봉이 낮아서 위험"이라는 문장은 이 서비스에 존재할 수
   없다.
3. **출구를 제시한다.** 모든 결과는 top 3 위험 요인과 "지금 할 수 있는 것"으로 끝난다. 위험을
   보여주는 목적은 불안이 아니라 점검이다.

## 3. 계산 모델

### 3.1 공통 설계 원칙

- **관점(perspective)** — 시작 시 남성 / 여성 / 밝히지 않음을 고른다. 이 선택은 (a) 문항 속 호칭
  치환, (b) 저장되는 `perspective` 값에만 영향을 준다. **점수와 가중치는 관점과 무관하게 동일하다.**
  성별로 가중치를 달리 줄 신뢰할 만한 정량 근거가 없고, 성별 고정관념의 점수화는 원칙 2 위반이다.
  대신 "같은 관계도 보는 자리에 따라 다르다"는 사실 자체를 제품으로 만든다 — 결과 페이지의 "상대의
  관점으로 다시 해보기"가 핵심 재방문·바이럴 루프다. 클라이언트의 "남자 입장 / 여자 입장" 요구는 이
  구조로 충족한다.
- **격차(gap) 원칙** — 경제·스펙 문항은 전부 격차의 체감과 갈등 빈도를 묻는다. 절대 소득·자산·키를
  입력받지 않는다 (개인정보 최소수집 + 서열화 방지 + 이탈률 감소).
- **문항 만점 = 축 내 가중치** — 별도 계수 없이, 문항의 최고 배점이 곧 그 문항의 상대적 중요도다.
  (경멸 10점 vs 나이차 4점 → 경멸이 2.5배)
- **UI** — 전 문항 단일 선택, 한 화면에 한 문항, 선택 즉시 자동 진행, 이전 버튼 제공.

**근거 표기** — `[G]` 비난·경멸·방어·담쌓기가 이혼의 강력한 예측 변수라는 부부 관계 연구 결과.

구간의 비중). `[H]` 직접 정량 근거 없이 관계 연구의 일반 지식에서 설계자가 정한 휴리스틱. 정확한
수치를 인용할 수 없는 항목은 모두 `[H]`로 표기했고, `/about`에도 같은 기준으로 공개했다.

### 3.3 점수 → 위험지수

```
axis_j = round( 100 × 축 획득점수 / 축 만점 )      # 0–100
S      = Σ_j ( w_j × axis_j )                      # 0–100
R      = 5 + 80 / (1 + e^( −0.07 × (S − 45) ))     # 5–85, 반올림 정수
```

검증용 참조값 (`tests/calc.test.mjs`가 고정):

| S | 0 | 25 | 45 | 65 | 85 | 100 |
|---|---|---|---|---|---|---|
| R | 8.3 | 20.8 | 45.0 | 69.2 | 80.4 | 83.3 |

**하한 5% / 상한 85%의 근거**
- 하한 — 모든 항목이 최선이어도 0%를 주지 않는다. 관계에 확실한 미래는 없다는 정직성 + 0% 결과의
  자랑 콘텐츠화 억제.
- 상한 — 최악의 조합에도 100%를 주지 않는다. "당신들은 끝났다"는 단정은 원칙 1 위반이며, 자가진단
  도구가 관계 포기를 부추겨서는 안 된다. 85%면 강한 경고를 전달하기에 충분하다.
- 로지스틱 — 중간 구간(S 35~55)의 변별력을 높이고 극단을 눌러, 대부분의 사용자가 "차이는 느껴지되
  극단적이지 않은" 결과를 받게 한다.

**실측 하한은 9%다.** 교제·혼인 기간 문항은 최선의 선택지도 0점이 아니어서(기본 위험), 세 계산기
모두 최선 응답의 지수가 9로 수렴한다. 의도된 동작이며 테스트가 이 값을 고정한다.

### 3.4 등급 구간

| 지수 | 등급 | 카피 방향 |
|---|---|---|
| 5–29 | 안정 | 인정 + 유지 요령 |
| 30–49 | 점검 | 중립 + 조기 신호 안내 |
| 50–67 | 주의 | 차분한 경고 + 구체 행동 |
| 68–85 | 경고 | 진지함 + 전문 상담 안내. "끝났다"류 표현 금지 |

### 3.5 top 3 위험 요인

문항 i의 기여도 = `100 × 획득점수_i × w_axis / 축만점_axis`. 전 문항 합이 정확히 S가 되므로,
"지수를 가장 많이 끌어올린 답변"이 말 그대로 성립한다. 기여도 0인 문항은 제외하며, 전부 0이면
"뚜렷한 위험 요인이 보이지 않습니다"로 대체한다. 요인별 라벨·해설·실행 제안은
`src/lib/calc/factors.ts`의 `FACTOR_COPY`에 전 문항(49개) 매핑되어 있다.

## 4. 결과 페이지

1. 지수 + 등급 배지 + 고정 고지문
2. 축별 가로 바 (레이더 대신 — 모바일 가독성 우선)
3. 가장 큰 위험 요인 top 3: 라벨 / 해설 / 지금 할 수 있는 것 / 내가 고른 답변
4. 관점 뒤집기 CTA + 결과 링크 만들기
5. 교차 유도(다른 계산기) + 관련 아티클 2편
6. 면책 고지

바 색은 값에 따른다(35 미만 sage / 60 미만 ink / 80 미만 amber / 이상 clay). 축이 아니라 값에
색을 매기므로, 사이트 어디에서든 같은 색이 같은 수준의 우려를 뜻한다.

## 7. 개발 범위

### MVP (완료)

홈 · 계산기 3종 전 문항 · 결과 페이지 · 공유(Supabase insert + `/r/{slug}`) · 아티클 5편 · `/about`

### 2차

1. 나머지 아티클 5편
2. 카카오톡 공유, slug별 동적 OG (Worker가 Supabase를 조회해 등급별 og:image 주입)
3. 집계 통계 노출 ("함께 본 사람들의 중앙값", n ≥ 100) + 관점별 비교 콘텐츠
4. 커플 비교 모드 — 두 사람의 결과를 한 화면에서

6. Turnstile 어뷰징 방어, slug 조회 전용 RPC 전환

### 구현 원칙 (유지할 것)

- 문항·점수·가중치·요인 카피는 전부 TypeScript config 데이터로 분리한다. 코드 수정 없이 튜닝할 수
  있어야 한다.
- S→R 참조값은 단위 테스트로 고정한다.
- **응답 데이터는 공유 버튼을 누르기 전까지 어떤 네트워크 요청에도 실리지 않는다** — 분석 도구
  이벤트 포함. 이 약속은 홈·FAQ·개인정보처리방침 세 곳에 적혀 있다.
